## Fase 3 — validação empírica Opção B (2026-05-20)

### R1 — Achatamento BM25 / gate ambiguidade

**Auditoria estática:** `search.py` tokeniza com `re.findall(r"\w+", text.lower())`, descarta candidatos com `raw_score <= 0`. `retrieval.py` gate `ambiguous_retrieval` (strict): `len(selected) > 1` e `score_margin < MIN_SCORE_MARGIN` (0.15), **após** `top >= MIN_SCORE` (1.5).

**Teste BM25 inline** (venv KernelBot, JSON real ISS, pipeline ingest simulado):

| Query | Aula | Chunks | Resultado |
|-------|------|--------|-----------|
| `transformers` | fluencia-ia/01 | 4 | df=4/4 → scores **0** em todos; `search` não devolve candidatos |
| `1fn` | sql-modelagem/05 | 2 | df=2/2, tf 5 vs 9 → scores **negativos** (-0.248 vs -0.293); filtrados |
| `embeddings` | fluencia-ia/01 | 4 | termo em todos os chunks → scores negativos, Δ top1-top2 **0.00023** |
| `decisão` | fluencia-ia/01 | 4 | só chunk 0 → score **1.195** vs 0 nos outros (corpo distingue) |

**Gates ACL (queries curtas):**

- `transformers` → `insufficient_context` (top=0 < 1.5), não `ambiguous_retrieval`.
- `1fn` / `1FN` → `informative_terms=[]` (len≤3, fora da allowlist) → `insufficient_context`.
- Empate artificial (margin 0.10 < 0.15, scores > 1.5) → `ambiguous_retrieval` confirmado.

**Resposta pergunta central:** keyword só no bloco meta (replicado em **todos** os chunks) → BM25 **não** desempata pelo corpo; IDF≈0 e scores ≤0. O motor **não** escolhe o bloco textual “certo” — hard stop por score insuficiente. Desempate só quando o termo tem TF diferencial no **body** de um subconjunto de chunks (ex. termo exclusivo de um chunk).

**Recomendação R1 (não implementada):** meta só no chunk 0 **ou** excluir meta do TF-IDF do BM25 (indexar `chunk_body` separado para score, injetar meta só no prompt). Trade-off: chunk 0 ganha recall lexical; exclusão do meta preserva 500 palavras úteis por chunk sem inflação repetida no índice.
