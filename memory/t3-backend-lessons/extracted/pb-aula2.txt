Ciclo de vida do sistema
Ao desenvolver um sistema de software não se deve simplesmente começar a programar.
Assim como na construção de uma casa, é essencial seguir um conjunto de etapas
organizadas, conhecido como ciclo de vida do sistema, que orienta o projeto desde a ideia
inicial até a entrega final.
Para isso, utilizamos uma estrutura de desenvolvimento que ajuda a definir:
- marcos importantes (Ex: finalização da análise)
- organizar as atividades (Ex: levantamento de dados)
- monitorar as entregas
Essa abordagem garante consistência entre as equipes, facilita a integração de novos
membros e contribui para a qualidade do sistema final.
                                                                                            2
Ciclo de vida do sistema


Quanto maior e mais complexo o projeto, mais evidente se torna a importância desse tipo
de estrutura. Ela oferece uma visão de alto nível sobre o processo, servindo como base
para o planejamento, monitoramento e controle do projeto.
Não se trata apenas do código, mas de todo o processo de criação de software, incluindo:
- Processos: Métodos e práticas para gerenciar e desenvolver software.
- Ferramentas: Software e tecnologias que facilitam o desenvolvimento e a gestão.




                                                                                           3
Ciclo de vida do sistema

Os processo incluim as seguintes atividades fundamentais:
- Análise e Especificação de Requisitos: Os requisitos são analisados para garantir que
sejam consistentes e completos, e então são especificados em detalhes para orientar o
design e a implementação.
- Design e Arquitetura do Software: A estrutura do sistema é projetada, definindo a
arquitetura e os componentes do software, além das interfaces entre eles.
- Implementação ou Codificação: Os desenvolvedores escrevem o código-fonte do
software, seguindo as diretrizes de design e padrões de codificação.


                                                                                          4
Ciclo de vida do sistema

Testes: O software é testado para encontrar e corrigir defeitos, garantindo que atenda aos
requisitos especificados e que funcione conforme esperado.
- Integração: Os componentes desenvolvidos separadamente são integrados para formar
o sistema completo.
- Implantação: O software é entregue aos usuários finais e instalado em seus ambientes
operacionais.
- Manutenção e Evolução: Após o lançamento, o software passa por manutenção para
corrigir defeitos e pode ser evoluído para atender a novos requisitos.


                                                                                             5
Ciclo de vida do sistema
O ciclo de vida do sistema é um processo estruturado que organiza o desenvolvimento de
software em etapas bem definidas.
Exemplo:
Na etapa de Requisitos, o foco está em entender o que o cliente realmente precisa. São
feitas entrevistas, questionários e reuniões para levantar essas necessidades. Ex:
identificar que um sistema de biblioteca deve permitir empréstimos, reservas e emissão
de relatórios mensais.
A fase de Análise aprofunda os requisitos coletados, definindo com clareza como o
sistema deve funcionar. São identificados os dados necessários, regras de negócio e
interações com os usuários. Ex: estabelecer que usuários com livros atrasados não
poderão fazer novos empréstimos.
                                                                                         6
Ciclo de vida do sistema

No Design o sistema começa a ser desenhado por meio de diagramas, arquitetura técnica
e interfaces. O objetivo é planejar a estrutura do sistema antes da programação. Ex:
desenho de telas de login, cadastros de livros e o modelo do banco de dados.
Durante a Implementação, os desenvolvedores começam a codificar o sistema com base
no design criado. Também são realizados testes para garantir que cada componente
funcione corretamente. Ex: programar o módulo de login e testar com diferentes tipos de
usuários.
Na fase de Instalação (Implantação), o sistema é instalado no ambiente real e
disponibilizado para os usuários.

Modelos de ciclo de vida
Principais modelos:
- Cascata
- Iterativo
- Incremental
- Processo Unificado (RUP)
- Ágeis
Cada modelo tem suas vantagens e limitações. A escolha do modelo mais adequado
depende da estabilidade dos requisitos, tamanho do projeto, prazos, orçamento, grau de
complexidade e nível de flexibilidade necessário.

                                                                                         12
Cascata

O Modelo em Cascata foi o primeiro modelo de ciclo de vida de software a ser
formalmente definido e documentado. Por muitos anos, foi amplamente utilizado em
projetos de desenvolvimento. Seu nome vem da forma como as fases do desenvolvimento
se sucedem, de maneira linear e sequencial, como uma cascata, em que cada etapa desce
para a próxima somente após a conclusão completa da anterior.
Princípio: é possível entender e planejar todo o sistema desde o início, antes de qualquer
linha de código ser escrita.
Exige um conhecimento profundo e estável dos requisitos do sistema logo nas fases
iniciais.

Cascata
O modelo é composto por seis fases principais.
1. Requisitos
Ocorre o levantamento e análise das necessidades do cliente ou usuário final.
Ferramentas: entrevistas, reuniões, questionários, análise de processos existentes.
Entregáveis: documento de requisitos detalhado.
2. Análise
Analisar tecnicamente como o sistema deverá funcionar. Transformar as necessidades em
um modelo lógico que oriente o design do sistema.
Ferramentas: modelagem de processos, diagramas de caso de uso, etc.
                                                                                        15
Cascata
3. Design
O foco é criar a arquitetura do sistema. Pode ser dividido em dois níveis:
- Design de alto nível: estrutura geral do sistema, definição de módulos e componentes.
- Design detalhado: definição da interface de usuário, estrutura de banco de dados,
algoritmos e fluxos internos.
Entregáveis: diagramas de classes, telas, arquitetura de software, modelo relacional do
banco de dados.
4. Implementação
Cada módulo é codificado conforme os padrões estabelecidos.

                                                                                          16
Cascata
5. Testes
O sistema completo é submetido a testes para garantir que atende aos requisitos
definidos.
6. Implantação
O sistema é entregue e instalado no ambiente do cliente, sendo acessível aos usuários
finais.
Após a implantação, podem surgir novas demandas(Manutenção). Envolve atualizações,
correções de bugs e melhorias contínuas que no modelo cascata tende a ser tratada
separadamente.

                                                                                        17
Cascata


Vantagens
- Fácil de entender, ensinar e gerenciar.
- Organização clara, com objetivos bem definidos por fase.
- Documentação robusta
- Bom para projetos bem definidos, que exigem rastreabilidade e formalidade.




                                                                               18
Cascata


Limtações
- Mudanças são difíceis de incorporar após o início da fase seguinte.
- Qualquer fase pode identificar erros que exigem revisões, o que é problemático no
modelo, já que voltar etapas é difícil.
- O cliente só vê o produto no final (sem entregas parciais)

Cascata
Exercício
Diante os seguintes cenários, o modelo em cascata seria uma escolha apropriada?
1) Um hospital contratou uma empresa de software para desenvolver um sistema de
controle de inventário de medicamentos e materiais hospitalares. Todos os requisitos
foram definidos previamente em um documento técnico elaborado pela equipe de
logística do hospital, com regras detalhadas sobre cadastros, movimentação de estoque e
emissão de relatórios.
Há a exigência de alta documentação, registro formal de todas as fases e auditorias
internas. O ambiente é bastante controlado, com baixo risco de mudanças, e os prazos e
orçamento já foram definidos com precisão no contrato.

                                                                                          20
Cascata

2) Uma Secretaria de Educação encomendou o desenvolvimento de um sistema de gestão
escolar para as escolas públicas estaduais. O projeto inclui funcionalidades como registro
de notas, controle de frequência e emissão de boletins.
Os requisitos foram amplamente discutidos e aprovados por meio de reuniões com
diretores e coordenadores pedagógicos. Como o sistema será utilizado em larga escala, é
exigida documentação completa, padronização e treinamentos formais para os usuários.
Não há expectativa de mudanças frequentes.

3) Uma startup está desenvolvendo uma nova plataforma de ensino online. A equipe tem
